# 测试约定

> 测试是 agent 的"第二只眼"。没有可执行的验收,一切交付都是意见而不是事实。

## 1. 测试的角色(哲学定义)

- **测试是 harness 的一部分,不只是产物的附属品。**
- 目的不是 100% 覆盖,而是让**未来的 agent 和人类**可以:
  - 在 30 秒内看懂"这段代码保证什么"。
  - 在 5 分钟内定位一个退化。
  - 在修改时获得即时反馈。
- Agent 的每个 PR 都要能回答一句话:**"如果我这次改错了,哪个测试会先红?"**

## 2. 分层与职责

| 层 | 目标 | 运行速度 | 必须要求 |
|---|---|---|---|
| **单元测试** | 最小行为单元 | 毫秒级 | 对所有新代码必须存在;与代码同目录或 `__tests__` |
| **集成测试** | 跨模块真实交互 | 秒级 | 涉及跨模块改动必须存在;可依赖临时容器 / fixtures |
| **E2E / 场景** | 真实用户路径 | 分钟级 | 关键用户故事必须存在 |
| **Smoke** | "服务能不能起" | 秒级 | 每次部署前跑 |
| **合同测试(Contract)** | 对外 / 对内 API 的契约 | 毫秒~秒 | 任何跨服务 / 跨客户端接口必须存在 |

## 3. 硬规定

- **任何生产代码改动 ≥ 10 行,必须同 PR 带测试**(修复 typo、批量重命名、文档改动例外)。
- 修一个 bug 必须**先写能复现 bug 的失败测试**,再让它变绿。
- **永远不许**:
  - 把测试 `skip` / `xfail` 绕过失败。
  - 把 `assert` 放宽到"几乎总是为真"的地步(比如 `assertTrue(result is not None)` 代替具体结构断言)。
  - 把 flaky 测试移出 CI,而不修它。
  - 在 CI 里加 `--exclude` 隐藏失败。
- **测试必须可独立运行、可乱序、可并行。**

## 4. 命名与结构

- 测试命名三段式:**`test_<被测对象>_<场景>_<期望>`**
  - ✅ `test_login_when_password_expired_returns_401`
  - ❌ `test_login_2`
- 一个测试**只测一件事**。多个断言可以,但断言的对象是同一行为。
- **AAA 结构**(Arrange / Act / Assert)清晰分三段。

## 5. 边界与等价类

对任何有输入的函数,至少测试:
- 正常路径 ×1
- 边界值(空 / null / 单元素 / 最大 / 最小)
- 错误路径(至少 1 种触发 / 至少 1 种被 reject 的理由)
- 并发路径(如适用)

## 6. 测试数据

- 用 **factory / fixture**,不要硬编码大数据串在测试中。
- 禁止测试依赖**外部真实**服务(网络、支付、邮件、短信)。用 fake / mock / contract test 替代。
- 时间相关代码必须能注入 clock(不许直接调 `time.now()` 做断言的依据)。
- 随机相关代码必须能注入种子。

## 7. 覆盖率

- **覆盖率不是目标,是信号**。
- 触发 review 的硬门槛(仅作为 review 提示,不自动 block):
  - 变更行覆盖率 < 70%:review persona `testing` 必须解释。
  - 核心模块变更行覆盖率 < 90%:默认视为不合入,除非 PR 中有书面理由。
- **严禁**:
  - 为了凑覆盖率加"调一遍就过"的测试。
  - `assertTrue(True)` 式空测试。

## 8. Agent 在写测试时的义务

- 先读 **相关目录下已有的测试文件**,**模仿其 style**。
- 如果这是新模块,测试先于实现(TDD-ish)。
- 每写完一批测试,自问:**"如果实现被换掉一个等价但错误的版本,我的测试能抓到吗?"**
- 用**mutation mindset**自检:随便改一处实现让它错,看会不会被抓。

## 9. Flaky 测试处理

- 发现 flaky 测试:**当 bug 处理**,不 skip,不 quarantine(最多标 `flaky` 并立即修)。
- 同一测试 30 天内 flaky 超过 2 次 → 必须**拆分或彻底重写**。
- 触发 `testing` persona review。

## 10. 性能测试

- 关键路径(首屏、主 API、核心算法)必须有**基准测试**(benchmark)。
- Benchmark 基线版本号化,PR 里有回归就 flag。
- "优化"的 PR 必须带 benchmark diff,不带不合入。

## 11. 属性测试 / 模糊测试(鼓励)

- 涉及解析、序列化、状态机、数值计算等的模块,**鼓励**加 property-based test(Hypothesis / fast-check / quickcheck)。
- 网络层 / 输入反序列化 / 解析器 **鼓励**加 fuzz。
- Agent 发现场景适合 property test 却没写时,在 ExecPlan 的"未做的权衡"字段里声明。

## 12. 测试对 harness 的反哺

- 某一类 bug **第二次**被同一个测试抓到 → 说明测试有效,不改。
- 某一类 bug **完全没有测试**,第一次抓到时 → PR 必须**同时**:
  - 修 bug
  - 写复现测试
  - **考虑**在 `.kiro/steering/` 添加一条约束,防止同类 bug 再诞生
- 某一类 bug **反复需要相似测试** → 触发抽象(测试辅助函数 / fixture / Matcher)。

## 13. 命令约定

项目根 Makefile / package.json / justfile 里必须存在:
- `test`:跑所有"快"测试(秒级以内)。
- `test:integration`:跑集成测试。
- `test:all`:跑全部。
- `test:focus <pattern>`:跑匹配 pattern 的测试(agent 经常需要)。
- `test:watch`:本地开发用(CI 不跑)。

## 14. 自检清单

- [ ] 本 PR 的所有改动都有**能抓住它**的测试吗?
- [ ] 我有没有 skip / xfail / 放宽断言?
- [ ] 我新加的测试命名是三段式吗?
- [ ] 我的测试独立、可乱序、可并行吗?
- [ ] 我引入新依赖了吗?是否 mock 了它?
- [ ] 我有 flaky 嫌疑的测试吗?

## 15. 反模式

| 反模式 | 为什么坏 | 正确姿势 |
|---|---|---|
| `skip` 掉失败测试 | 债永远复利 | 修代码 |
| `assertEqual(a, a)` 式空测试 | 覆盖率造假 | 写实际行为断言 |
| 一个测试几十个断言 | 失败定位慢 | 拆成多个 |
| 测试里 sleep 等异步 | flaky 根源 | 用时间注入 / 事件 await |
| 直接调外部服务 | 网络抖动 = CI 抖动 | 用 fake / contract |
| "改了个 log,反正不影响测试" | 退化的起点 | 还是跑一次全测试 |
